# AGENTS.md

## Cursor Cloud specific instructions

This repo is a single **Foxglove extension panel** ("DIY DVR"), written in TypeScript/React and built with `pnpm`. There is no long-running dev server for the extension itself — it runs *inside* the external Foxglove desktop/web app. See `README.md` and `package.json` scripts for the standard commands.

### What can and cannot run here
- The **Foxglove app is external** and cannot run in this headless VM, so full GUI/E2E testing of the panel inside Foxglove is not possible here. Verify the runnable halves of the product instead (below).
- **Core writer path (offline, no browser):** `pnpm run validate:mcap /tmp/sample.mcap` exercises `buildMcap` + `schemaRegistry` + `inferSchema` and writes a real indexed MCAP. This is the best "does the product logic work" smoke test.
- **Live `ws://` source — `demo-server/` (the primary demo):** a self-contained synthetic warehouse-robot feed (map/plan/pose/tf/scene/odom/imu/battery/status/diagnostics), no MCAP needed. Run `uv run python main.py` from `demo-server/` (or `./serve.sh start`), default `ws://127.0.0.1:8765`. It has a headless self-test that steps the sim in fake time and encodes every message: `cd demo-server && uv run python test_sim.py`. `uv run` auto-creates `demo-server/.venv` from `pyproject.toml`/`uv.lock` on first use (git-ignored).
- **Live `ws://` source — `test-server/serve.py`:** replays an existing MCAP over a Foxglove WebSocket, looping forever. Run `uv run test-server/serve.py --file <path.mcap>` (e.g. the file from `validate:mcap`).
- Both `demo-server` and `test-server` **default to the same port 8765**, so only one can run at a time (or pass `--port`).

### Non-obvious gotchas
- **WebSocket subprotocol:** `test-server` uses `foxglove-sdk>=0.4.0`, whose server negotiates the **`foxglove.sdk.v1`** subprotocol — NOT the older `foxglove.websocket.v1`. A client that only offers the old subprotocol gets an HTTP 400 handshake rejection.
- `pnpm run lint` and `pnpm run typecheck` are both clean. There is no unit-test suite; validation is `validate:mcap` + manual testing in Foxglove.
- **`pnpm run package` must stay byte-reproducible.** The extension registry pins an exact `sha256sum` per release. `foxglove-extension package` zips files with a fixed date but lets jszip stamp the auto-created `dist/` folder entry with the build wall-clock time, so `scripts/normalize-foxe.mjs` rewrites all zip timestamps afterwards. CI rebuilds and compares hashes; don't bypass the normalize step.
- **pnpm config lives in `pnpm-workspace.yaml`, not `package.json`.** pnpm >=10 ignores the `pnpm` field in `package.json`, so `nodeLinker`, `allowBuilds`, and `overrides` are all in the workspace file.
- `src/generatedWorkerSource.ts` is git-ignored and regenerated by `pnpm run build` / `pnpm run bundle:worker`. Don't commit it.

### System tools (not installed by the update script)
- The Python live sources (`demo-server/`, `test-server/`) need **`uv`** (https://astral.sh/uv/), and MCAP file inspection uses the external **`mcap` CLI**. Neither is a project dependency and the `pnpm install` update script does not install them; install them ad hoc if missing. `uv run` fetches the Python deps automatically (`demo-server` from its `pyproject.toml`/`uv.lock`; `test-server` from PEP 723 inline deps in `serve.py`).
