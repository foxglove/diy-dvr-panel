# AGENTS.md

## Cursor Cloud specific instructions

This repo is a single **Foxglove extension panel** ("DIY DVR"), written in TypeScript/React and built with `pnpm`. There is no long-running dev server for the extension itself — it runs *inside* the external Foxglove desktop/web app. See `README.md` and `package.json` scripts for the standard commands.

### What can and cannot run here
- The **Foxglove app is external** and cannot run in this headless VM, so full GUI/E2E testing of the panel inside Foxglove is not possible here. Verify the two runnable halves of the product instead (below).
- **Core writer path (offline, no browser):** `pnpm run validate:mcap /tmp/sample.mcap` exercises `buildMcap` + `schemaRegistry` + `inferSchema` and writes a real indexed MCAP. This is the best "does the product logic work" smoke test.
- **Live `ws://` source harness:** `test-server/serve.py` replays an MCAP over a Foxglove WebSocket (default `ws://127.0.0.1:8765`, the standard Foxglove WS port, loops forever). It is the stand-in for a live robot feed that drives the panel. Run with `uv run test-server/serve.py --file <path.mcap>` (you can use the file produced by `validate:mcap`).

### Non-obvious gotchas
- **WebSocket subprotocol:** `test-server` uses `foxglove-sdk>=0.4.0`, whose server negotiates the **`foxglove.sdk.v1`** subprotocol — NOT the older `foxglove.websocket.v1`. A client that only offers the old subprotocol gets an HTTP 400 handshake rejection.
- **`pnpm run lint` currently reports 3 pre-existing errors** (in `src/DvrPanel.tsx` and `src/mcap.worker.ts`). The lint tooling itself works; these are code-level issues unrelated to environment setup.
- **`pnpm run pretest` is broken** — it calls a non-existent `foxglove-extension pretest` subcommand. There is no real unit-test suite; validation is `validate:mcap` + manual testing in Foxglove.
- `src/generatedWorkerSource.ts` is git-ignored and regenerated by `pnpm run build` / `pnpm run bundle:worker`. Don't commit it.

### System tools (not installed by the update script)
- The optional `test-server` needs **`uv`** (https://astral.sh/uv/), and MCAP file validation uses the external **`mcap` CLI**. Neither is a project dependency; install them ad hoc if you need the live-feed harness or `mcap doctor`/`mcap info`. `uv run` auto-fetches the Python deps (`foxglove-sdk`, `mcap`) declared inline in `serve.py`.
